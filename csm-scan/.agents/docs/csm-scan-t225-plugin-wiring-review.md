## Findings (non-blocking, P3)

1. **Retry drops provider observations for the retried dimension.** `run.mjs:118-128` replaces a retried dimension's `findings` with the raw re-scan result (`retry.findings`), which lacks the `providerObservations` merged at `run.mjs:960-965` before `processExpandedRepo`. A dimension re-scanned under the <40 coverage threshold therefore renders with no plugin/generic evidence in the final output, contradicting AC12 for such repos. Not exercised by any test (fixture/probe coverages all ≥50, retries never fire) — latent. Fix: re-apply `mergeProviderEvidence` to `validated.findings` after the retry loop (or recompute provider evidence in `processExpandedRepo`).
2. **Near-max plugin observations can trip the fail-before-write privacy node bound.** `assertFindingsPrivacy` re-checks the six new dimensions' full `findings` (now including `providerObservations`) at `PRIVACY_LIMITS.maxNodes = 20000` (`privacy.mjs:14`). `PROVIDER_OBSERVATIONS_BOUND = 2048` (`run.mjs:603,757`) implies ~22k nodes on its own, so a plugin contributing near-max observations to one new dimension (reachable: 16 rules × 128 matches) aborts a legitimate run with `PRIVACY_LEAK` (fail-closed but wrong). Fix: exclude already-filtered provider observations from the gate, raise the node limit for this call, or lower the merge bound for the six new dims.
3. **Plugin match caps are silently truncated without disclosure.** `run.mjs:776` ignores `evaluateRules(...).capped`; matches are per-plugin capped at 2048 and per-rule at 128, so evidence can truncate silently for a large plugin/repo, unlike the generic catalog's threaded `capped` flag (`runtime-catalog.mjs:614`, `assurance-catalog.mjs:753`). Fix: thread a cap disclosure (reporter note or envelope flag).
